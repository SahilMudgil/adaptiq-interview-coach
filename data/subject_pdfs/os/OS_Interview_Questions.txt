Operating Systems Core Interview Questions & Answers

Q1. Explain The Main Purpose Of An Operating System?
Operating systems exist for two main purposes:
1. Ensure the computer system performs optimally by managing hardware and computational resources (CPU, memory, I/O).
2. Provide a clean abstraction environment for the development and execution of user applications.

Q2. What Is Demand Paging?
A lazy-swapping memory management technique where pages are loaded from secondary storage (disk) into physical RAM only when requested (demanded) during execution, generating a page fault if not present.

Q3. Advantages Of A Multiprocessor System?
1. Increased throughput (more work done in less time).
2. Economy of scale (shared peripherals, memory, power supplies).
3. Increased reliability and fault tolerance (graceful degradation / failover).

Q4. What Is the Kernel?
The foundational core of an operating system running in privileged supervisor mode. It connects user-space applications to physical hardware, handling process scheduling, memory allocation, interrupt handling, and device I/O.

Q5. What Are Real-Time Systems?
Operating systems subject to strict, deterministic time constraints:
- Hard Real-Time: Missing a deadline causes total system failure (flight control, medical pacemakers).
- Soft Real-Time: Deadlines are important but missing one only degrades quality of service without catastrophe (video streaming).

Q6. What Is Virtual Memory?
An architectural abstraction that decouples process logical address space from physical RAM. Enables processes to execute even if their address space exceeds available physical memory, using paging, disk backing stores, and translation lookaside buffers (TLB).

Q7. Objective Of Multiprogramming:
To maximize CPU utilization by organizing jobs so the CPU always has a process ready to execute whenever the active job performs I/O.

Q8. What Are Time-Sharing Systems?
Logical extension of multiprogramming where the CPU switches rapidly between tasks (preemptive multitasking) giving users the illusion of dedicated interactive execution.

Q9. What Is SMP (Symmetric MultiProcessing)?
A multiprocessor architecture where two or more identical processors share a common main memory and OS instance, communicating via shared memory buses.

Q10. Asymmetric Clustering:
A high-availability clustering model where one standby machine remains in hot-standby monitoring the active server, taking over only if the active server fails.

Q11. What Is A Thread?
A lightweight unit of CPU execution within a process. Threads share the parent process's address space, code, and global data, but possess private thread IDs, program counters, register sets, and stack frames.

Q12. Benefits Of Multithreaded Programming:
1. Responsiveness (interactive UI remains active during background computation).
2. Resource sharing (threads naturally share memory and files).
3. Economy (thread creation and context switching are much cheaper than processes).
4. Scalability across multicore architectures.

Q13. CPU Scheduling Algorithms:
- FCFS (First-Come, First-Served): Non-preemptive, suffers from convoy effect.
- SJF / SRTF (Shortest Job First / Shortest Remaining Time First): Optimal average waiting time, risk of starvation.
- Priority Scheduling: Preemptive or non-preemptive, uses aging to prevent starvation.
- Round Robin (RR): Preemptive, designed for time-sharing, allocates fixed time quantum (10-100ms) circularly.

Q14. Necessary Conditions For Deadlock (Coffman Conditions):
All four must hold simultaneously:
1. Mutual Exclusion: At least one resource must be held non-shareably.
2. Hold and Wait: A process holds resources while requesting additional ones.
3. No Preemption: Resources cannot be forcibly seized; only released voluntarily.
4. Circular Wait: A closed loop of processes {P0, P1, ... Pn} exists where Pi waits for Pi+1.

Q15. Deadlock Handling Strategies:
- Prevention: Invalidate at least one of the 4 Coffman conditions.
- Avoidance: Banker's Algorithm (allocates resources only if system remains in a "safe state").
- Detection and Recovery: Resource Allocation Graphs (RAG), process termination, or resource preemption.
- Ignorance: Ostrich algorithm (used by Unix/Windows for performance).

Q16. RAID Levels:
- RAID 0: Block-level striping, no redundancy, highest speed.
- RAID 1: Disk mirroring, high redundancy.
- RAID 5: Block-level striping with distributed parity (tolerates 1 disk loss).
- RAID 6: Dual distributed parity (tolerates 2 simultaneous disk losses).
- RAID 10 (1+0): Striped mirrored sets.

Q17. Logical vs Physical Address Space:
- Logical Address: Generated by CPU during program compilation/execution (virtual address).
- Physical Address: Actual physical memory location in RAM loaded into the Memory Address Register (MAR) via MMU translation.

Q18. Dynamic Loading vs Overlays:
- Dynamic Loading: Subroutines are loaded into memory only when invoked at runtime, conserving physical memory.
- Overlays: Historical technique where programmers manually swap code sections into a shared memory region when programs exceed total RAM.

Q19. Paging and Page Replacement:
- Paging: Divides logical memory into fixed-sized "pages" and physical memory into matching "frames", eliminating external fragmentation.
- Page Fault: Interrupt triggered when a referenced page is not present in physical RAM.
- Replacement Algorithms: FIFO, Optimal (MIN), LRU (Least Recently Used), Clock/Second Chance.

Q20. Fragmentation:
- Internal Fragmentation: Allocated memory block is slightly larger than requested; unused space inside the partition.
- External Fragmentation: Total free memory space is sufficient to satisfy a request, but storage is non-contiguous.

Q21. Process States:
- New: Process is being instantiated.
- Ready: Loaded in RAM, waiting for CPU assignment by scheduler.
- Running: Instructions executing on CPU.
- Waiting / Blocked: Waiting for I/O completion or event signal.
- Terminated: Execution finished, resources deallocated.

Q22. Thrashing:
Severe system state where the operating system spends more time servicing page faults and swapping pages in/out than executing user instructions. Resolved by reducing degree of multiprogramming or increasing RAM.

Q23. Virtual File System (VFS):
An abstraction layer within the kernel providing an object-oriented interface (vnodes) decoupling generic file operations (read, write, open) from concrete filesystem implementations (ext4, NTFS, NFS).

Q24. Interrupts and Context Switching:
- Hardware Interrupt: Signal generated by peripheral devices notifying CPU of asynchronous events.
- Software Interrupt / Trap: Triggered by exceptional condition (divide by zero) or system call (`syscall`).
- Context Switch: Saving the state of the currently executing process (registers, PC) in its PCB and restoring the state of the newly scheduled process.

Q25. Caching and Spooling:
- Caching: Storing high-frequency data in small, ultra-fast memory (L1/L2/L3 cache, buffer cache) to bridge speed disparities.
- Spooling (Simultaneous Peripheral Operations On-Line): Buffering data for slow devices (like printers) onto disk queues.
